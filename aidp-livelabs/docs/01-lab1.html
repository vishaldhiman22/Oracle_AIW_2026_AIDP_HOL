Lab 1: Bronze, Silver, and Gold

Introduction

Build a data foundation for Seer Construction using three focused notebooks. Read five source CSV files, reconcile their business identifiers, and prepare project context and milestone features.

Part A: Load Bronze

Before rerunning Lab 1

No manual table deletion is needed. Each write cell already drops and recreates its own named target without a backup: five Bronze, five Silver and two Gold tables. Source CSVs/PDFs, schemas, volumes, registered models and unrelated objects remain in place.

Run Bronze → Silver → Gold → Lab 2 after changing source data. An upstream rerun does not refresh downstream tables automatically; old predictions remain until Lab 2 replaces them. For a Silver-only change, start at Lab 1B; for a Gold-only change, start at Lab 1C, provided its inputs are current. Always run that notebook's setup and subsequent cells in order.

Avoid concurrent writers. If a write fails after its drop, the target may be absent; fix the cause and rebuild it before continuing downstream. Refresh the catalog and recheck counts and lineage. See complete rerun guidance.

  1. Select workspace seer_livelabs_20260922.
  2. Open Shared → seer-aidp-livelabs → notebooks → Lab1A_Bronze_Ingestion.ipynb.
  3. Attach seer_livelabs_spark. Wait for the cluster to be ready.
  4. Read the opening Markdown. Each load recreates its named Bronze table without a backup. Do not run concurrent writers.
  5. Run the small setup cell. It reads the shared configuration, defines the input volume and Bronze namespace, and runs CREATE SCHEMA IF NOT EXISTS for Bronze.
  6. Run the five CSV load cells in order.

Each cell reads a CSV with headers, keeps columns as strings, replaces empty values with empty strings, and saves one Delta table.   2. Continue to the Silver notebook.

Part B: Transform Silver

  1. Open Lab1B_Silver_Transformations.ipynb and attach the same cluster.
  2. Run its setup cell. It defines the Bronze and Silver namespaces, imports pyspark.sql.functions, and runs CREATE SCHEMA IF NOT EXISTS for Silver.
  3. Run the five transformation tasks in order. Read the inline comments before executing each one.

Task 1: Suppliers

  • Trim names and standardize Atlas abbreviations.
  • Normalize qualification codes, certifications, and location spelling.
  • Group duplicate source records by canonical supplier name.
  • Generate a stable supplier ID and retain original standardized rows in source_records.
  • Preserve conflicting qualifications and missing certification flags instead of guessing a correction.

Task 2: Assets

  • Read project names from the Bronze schedule table.
  • Use the workshop's explicit one-asset-per-project mapping.
  • Rename source fields consistently and left-join the project names.
  • Save three canonical asset records. This mapping is a fixture rule, not general entity resolution.

Task 3: Purchase orders

  • Resolve asset IDs using the project reference.
  • Expand supplier source IDs for a temporary join lookup.
  • Preserve unmatched suppliers with left joins.
  • Normalize purchase-order status and convert decimal currency amounts into integer USD cents.

Task 4: Inspections

  • Left-join assets by project.
  • Add consistent project and asset identifiers.
  • Trim and uppercase inspection status. Keep source dates unchanged.

Task 5: Milestones

  • Left-join scheduled activities to assets by project.
  • Normalize milestone status.
  • Preserve planned, actual, and extraction dates for Gold calculations.

Run the final read-only cell to print every Silver table name and its current record count.

Each transformation task recreates and writes exactly one Silver table. There is no Silver validation task, no answer-key read, and no quarantine or summary table. Known source issues remain in the data for Lab 2's investigation.

Part C: Build Gold

  1. Finish the Bronze and Silver notebooks.
  2. Open Lab1C_Gold_Project_Data.ipynb and attach the cluster.
  3. Run setup. It runs CREATE SCHEMA IF NOT EXISTS for Gold, which stays in seer_livelabs_20260922.seer_gold.
  4. Run Task 1: Build project context. It aggregates orders, supplier status, and inspections before joining to assets and the selected context milestone. Aggregating first avoids multiplying costs.
  5. Notice that source extraction time is separate from this run's refresh timestamp.
  6. Run Task 2: Build milestone features. It selects unfinished milestones due 1–30 days after the fixture date, then computes nine numeric model features.
  7. Browse project_context and milestone_features in the Gold schema.

Task 1 uses spark.sql() with named CTEs for the project-context aggregates and joins. Task 2 continues to use PySpark DataFrame operations and pyspark.sql.functions. Each cell recreates its target with one DROP TABLE IF EXISTS statement, then writes the complete Spark plan with format("delta").mode("overwrite").saveAsTable(...). There are no Python UDFs or pandas round trips.

Part D: Inspect lineage

  1. Run the notebooks sequentially, or use the four-task workflow after it is deployed.
  2. Refresh the catalog and open the current milestone_features table.
  3. Select Actions → Lineage (Preview).
  4. Trace Gold inputs back to Silver and then Bronze.
  5. Inspect the separate Bronze, Silver, and Gold task nodes. AIDP process nodes between tables are expected.

Native lineage must be checked after execution. Keeping Spark source plans is necessary but is not proof of capture. See the workflow guide for verification.
